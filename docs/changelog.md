# Changelog

Instrument and design changes, one line each: date | instrument | change | reason. Each line notes whether held-out data was involved.

- 2026-11-18 | platform | runs move to WSL2 (Ubuntu), working on the Windows checkout through /mnt/c; uv, pytest and vf-* run only from WSL | verifiers 0.4.1 imports fcntl and uses os.killpg, so its trace and CLI can't run on native Windows; /mnt/c keeps one checkout shared with Windows tools, at the cost of slower file I/O (no held-out data involved)
- 2026-11-18 | pins | Python 3.11, verifiers==0.4.1 (environment package), prime==0.22.0 via uv tool install (not a project dependency) | exact pins so results are tied to a known library version; verifiers needs >=3.11,<3.15 and prime <3.14 (no held-out data involved)
- 2026-11-18 | layout | virtual uv workspace root (research code, dev tools, one lockfile) plus the environment package environments/neuro_grounded_qa/ (Hub ID neuro-grounded-qa) | only the environment package ships to the Hub; tests, docs and scripts stay out of it (no held-out data involved)
- 2026-11-18 | run config | configs/local.toml as the default: local subprocess agent runtime, outputs/ gitignored, no model or endpoint set | vf-run's defaults send prompts to Prime Inference and run the agent in a Prime sandbox; every run should name its model and endpoint explicitly (no held-out data involved)
- 2026-11-18 | imports | import verifiers.v1 as vf | the top-level verifiers package re-exports nothing in 0.4.1 (no held-out data involved)
- 2026-11-18 | platform | venv moved to the WSL filesystem (~/.venvs/ngq-<checkout>) through a committed .envrc read by direnv; the code stays on /mnt/c | uv run pytest -q took 1m18.6s with the .venv on /mnt/c and 5.4s with the venv on the WSL filesystem (no held-out data involved)
- 2026-11-19 | expansion test | added the expansion test to docs/question_set_design.md (criteria C1–C8 gating, R1–R4 reported; sizing 200 + 100 held-out at 3× headroom; decision rule expanding to AD, PD, FTD, ALS, HD and DLB on failure); all thresholds proposed, pending approval | the domain choice must rest on what the graph contains, written down before either graph is measured or any question drafted (no held-out data involved)
- 2026-11-19 | subgraph measurement | method for the expansion-test measurement: canonical edges (PrimeKG's reverse copies collapsed; drug_protein split by display_relation; OptimusKG relations keyed as label/relation), subgraphs (a) induced on N1, (b) every edge touching N1, (c) as (b) expanding only through 1-hop nodes at or below the 90th/95th/99th full-graph degree percentile; absence checked against the full graph; proposed seed = main AD node plus its subtypes in each graph's disease hierarchy | makes the candidate counts reproducible and states the choices behind them; graph, seed, definition and percentile remain Kaitlin's decisions (no held-out data involved)
- 2026-11-18 | contracts (evidence, item, output, retrieval) | added `neuro_grounded_qa.contracts`: kind-tagged evidence units with `E:` edge IDs (`P:` reserved), graph-neutral entities, the `EvidenceStore` protocol and an in-memory fixture store; `QuestionItem` (a `vf.TaskData` subclass with gold triples, gold evidence, answerability, `evidence_scope` and provenance); the final-output schema and a strict `parse_output`; the tool result payload; contract tests on synthetic fixtures | the data, reward and harness code build against one committed interface instead of each other's work in progress; the kind tags and `evidence_scope` let phase-2 passages be added without reworking phase 1 (no held-out data involved)
- 2026-11-18 | retrieval | `retrieved_ids(trace)` counts a tool message only if its `tool_call_id` matches a call in a model-sampled assistant message, the tool message descends from that message in the trace's parent chain, and its content parses as the tool payload; IDs are read from the payload, never from free text; rejections are recorded by reason | Verifiers' `trace.tool_messages` includes prompt-supplied tool results, so a reward built on it pays for evidence the model never fetched; the descendant check also rejects tool messages that reuse a real call's ID elsewhere in the graph (no held-out data involved)
- 2026-11-18 | output format | claims are triples of graph entity IDs and the graph's own relation labels, copied from tool results, each citing evidence IDs; names are optional and never scored; parsing is strict (one JSON object, optionally in one fenced block; extra keys, duplicate keys and mixed answer-and-abstain objects fail) | lets the support check be exact equality in code instead of synonym matching, and leaves no gap between how the parser and the reward read an output (no held-out data involved)
- 2026-11-19 | items (false premise) | added `answerable="correctable"`; `false_premise` items may be `no` (premise absent from the graph: only abstaining is correct) or `correctable` (an edge contradicts the premise: abstaining or a cited correction is correct, with the correction as gold points); false-premise items carry a code-verified `premise` triple, which never equals a gold point | correcting a false premise is a legitimate answer, and mapping every false premise to `no` would have penalized it (no held-out data involved)
- 2026-11-19 | retrieval | strict retrieval also accepts only one result per call: the first tool message in node order that passes the provenance checks for its nearest issuing ancestor and call ID; later ones are rejected as `duplicate_result` | a tool message reusing a real call's ID later on the same branch descended from the issuer and still counted, which a tampering harness could exploit; matching the nearest issuer keeps per-turn ID reuse (`call_0`) working (no held-out data involved)
- 2026-11-19 | evidence and support check | edges are undirected facts (one row per edge, subject/object order arbitrary but stable); shared helpers `same_fact` and `supports` in `contracts.facts` match a triple in either order with an identical relation label, for both the support check and gold-point coverage | PrimeKG doesn't encode direction reliably and ships many edges twice, once per orientation; one rule in one place keeps the data and reward code from comparing triples differently (no held-out data involved)
- 2026-11-19 | items and evidence store | `QuestionItem` requires `id` and a non-empty `prompt` and gains optional `template_id`; new validators: `partial` (and `correctable`) items need a gold point, `answerable="no"` items have no gold evidence, each gold point cites at least one evidence ID, all within `gold_evidence`; the `EvidenceStore` protocol adds `entity(entity_id)` and a `build_id` (graph name, version, build hash), defaulting to `"fixture"` in the in-memory store | items need durable IDs and template provenance; the validators catch inconsistent gold before it reaches the reward; evidence IDs only mean something within one graph build, and tools need to resolve entity IDs directly (no held-out data involved)
